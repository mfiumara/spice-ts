## Method

- ngspice: `ngspice -b -r <raw> <identical-fixture> (HOME=<tmp> with .spiceinit "set filetype=ascii")`. Status success means exit 0 and at least one op/dc/ac/tran/pz/noise/disto plot in the raw file; failed/unsupported is classified from ngspice's own output.
- spice-ts: `@spice-ts/core simulate(<identical-fixture>) in a bounded child process (no parse() pre-check)`. The runner and metric are corpus-f's (`benchmarks/corpus/corpus-f/{outcomes,lib}.ts`), imported unchanged. Gap buckets apply the corpus-h rules in `lib.ts` first, then the corpus-g and corpus-f rules.
- matched = both engines succeed, every spice-ts analysis has an ngspice counterpart, and for every common signal max|spice-ts - ngspice| <= 0.01 x max(peak |ngspice signal|, floor), with the corpus-f floor: 0.0001 V for node voltages, 1e-10 A for branch currents, 1e-12 otherwise. Errors are taken at spice-ts points with ngspice interpolated (transient breakpoint alignment as in the aggregate report).
- "worst" is that normalised error for the worst signal.
- Bounds: ngspice 600 s, spice-ts 120 s per fixture. The outcome hash excludes environment, tools.node, ngspice.analyses, spiceTs.analyses.
- Regenerate: `pnpm build && spice-heavy pnpm exec tsx benchmarks/corpus/corpus-h/parity.ts`; verify without writing: `spice-heavy pnpm exec tsx benchmarks/corpus/corpus-h/parity.ts --check`.
- Machine: darwin 27.0.0 arm64, Apple M5 Pro; Node v22.23.1.
- 13 fixtures share a file name with a fixture of another public corpus (different bytes). They are marked † below.
