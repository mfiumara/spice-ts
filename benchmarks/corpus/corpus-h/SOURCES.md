- Candidates: every git-tracked file at the pinned revision of each source, under the listed roots, whose name ends in .cir, .sp, .net, .ckt, .spi, .deck, .cki or .spice.
- skipped-path: the path is under a prefix the source table skips, with the reason given there.
- already-in-corpus: the bytes (or the bytes without a terminal newline) hash-match a fixture of an existing public corpus (classic, ngspice, xyce, corpus-d/e/f/g and the SPICE3 translations).
- duplicate-content: the bytes hash-match an earlier candidate (sources in key order, paths sorted); the first is kept.
- licence: the deck carries a copyright or licence notice that the repository-wide licence cannot be assumed to cover (corpus-f rule, unchanged). Not committed.
- not-utf8: the bytes are not lossless UTF-8, so spice-ts cannot receive the identical deck through its string API.
- host-command: the deck runs shell or gnuplot commands on the host.
- not-self-contained: the deck loads another file (.include/.lib/OSDI/source) or names a sibling upstream file, so it cannot run unchanged in an isolated directory.
- no-analysis: no analysis card or control-block analysis command.
- ngspice-no-reference: ngspice-47 run on the identical bytes (batch mode, 60 s bound) did not exit 0 with at least one op/dc/ac/tran/pz/noise/disto plot in its raw file, so there is no reference to compare against. The probe result and ngspice's first error line are recorded in ngspice-probe.json. spice-ts is not run during selection.
- directory-cap: at most 16 decks per upstream directory (per source), first in path order, among decks that passed every rule above. Capped decks are listed below for later batches.

## Skipped sources

- KiCad eeschema simulation demos (`demos/simulation`): Still skipped as in corpus-g: the demos are `.kicad_sch` schematics under CC BY-SA 4.0, so a netlist would be a kicad-cli-generated derivative, and most load vendor model libraries. The KiCad QA SPICE netlists (`qa/data/eeschema`, GPL-3.0-or-later) are committed upstream as SPICE text and are candidates here instead.
- ISCAS-85/89 benchmark netlists: Gate-level `.bench` files, not SPICE: running them needs a transistor-level translation with a chosen cell library (an adaptation). Not committed.
- ngspice examples/tests decks that corpus-f deferred as not self-contained (204 decks): They need their companion model/stimulus files and a spice-ts include resolver in the runner; the corpus-f runner passes the deck as a string without one. Left for a dedicated batch so this one stays a pure identical-bytes, single-file comparison.
- Openly licensed textbook circuits and vendor application notes / LTspice example circuits: Textbook netlists are embedded in prose (extraction is an adaptation, per-book licence review needed); vendor and LTspice example terms do not grant redistribution. Not committed.
- Gnucap regression tests beyond corpus E: Mostly gnucap-native syntax; corpus E already holds the batch that ngspice can read. Not re-surveyed here.
- Decks with their own copyright or licence notice in any source: Listed below as `licence` exclusions and not committed.
