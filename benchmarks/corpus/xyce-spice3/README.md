# xyce-spice3: SPICE3 translations of the ngspice-rejected Xyce fixtures (#524, lane 3)

Seven of the 20 fixtures in `benchmarks/corpus/xyce` cannot be compared because ngspice rejects
their Xyce dialect (five zero-print-step `.tran`, one `.STEP`, one PSpice level-2 diode). This
corpus holds SPICE3/ngspice-dialect companions for them. The verbatim originals are untouched and
keep their current status in the aggregate report.

Not yet registered in `benchmarks/aggregate-report.ts` or `benchmarks/SOURCES.md`: #524 lane 4 does
that (both files are hash-pinned by the aggregate report).

## Files

- `fixtures/**.cir`: translated decks, generated by `benchmarks/translate/xyce-to-spice3.ts` from
  the hash-pinned originals. Each deck keeps the original title line first, then a GPL modification
  notice (upstream URL, original path and SHA-256, licence, date, list of changes). Every changed
  original line stays in the deck as a `* [xyce-to-spice3] original:` comment.
- `manifest.json`: generated by the translator. Per fixture: the original's provenance, the
  translation status (`translated` with the rules applied, or `unsupported-translation` with the
  reasons), and the translated deck's path and SHA-256.
- `LICENSE-NOTICE.md`, `COPYING.txt`: byte-identical copies of the upstream Xyce_Regression
  copyright/licence notice and GPLv3 text, as in `benchmarks/corpus/xyce`.
- `reference/`: Xyce_Regression's own references from the same pinned revision, unmodified:
  gold outputs `OutputData/DIODE/diode.cir.prn` and `OutputData/NJFET_DC/njfet.cir.prn`, plus the
  analytic gold-standard scripts `Netlists/CAPACITOR/{capacitor,rc_osc}.cir.prn.gs.pl`, which
  `compare.ts` transcribes (same constants, including `mpi = 3.1415927`).
- `compare.ts` -> `report.json`: runs ngspice and spice-ts on the identical translated bytes with
  the aggregate report's runners and metric, then each engine against the Xyce reference.

pnpm exec tsx benchmarks/translate/xyce-to-spice3.ts           # regenerate fixtures + manifest

## Translation rules

Purely syntactic and circuit-preserving. A construct without an exact SPICE3 equivalent is never
approximated; the fixture is marked `unsupported-translation`. The exact rule texts are in
`manifest.json` (`source.mechanicalAdaptation`) and `benchmarks/translate/xyce-to-spice3.ts`.

1. `tran-zero-tstep`: `.tran 0 TSTOP` -> `.tran (TSTOP-TSTART)/50 TSTOP`. ngspice needs TSTEP > 0.
   That value is the smallest TSTEP at which ngspice's output no longer depends on TSTEP. Checked
   on all three translated `.tran` decks: the ngspice raw data is byte-identical for TSTEP =
   span/50, 10x and 50x that, and differs at span/100.
2. `timeint-tolerances-removed`: `.options timeint reltol=.. abstol=.. [method=7]` is commented
   out. TIMEINT is Xyce's time-integrator option package and SPICE3 has no equivalent; METHOD=7 is
   trapezoidal, the SPICE3 default. Both engines run at default tolerances, which are looser than
   the upstream test's.
3. `step-source-to-nested-dc`: `.step Vgs 0 -1.875 -0.625` + `.DC VDS 0 15 1` ->
   `.DC VDS 0 15 1 Vgs 0 -1.875 -0.625`. Upstream already uses this form in
   `NJFET_DC/njfet-2109.cir`.
4. `capacitor-ic-to-dot-ic`: a grounded capacitor with `IC=V` in a `.tran` without UIC also gets
   `.ic v(node)=V`. Xyce always applies device ICs and enforces them in the operating point, like
   `.IC`. SPICE3 ignores an instance IC without UIC but does enforce `.ic`.
5. `print-brace-expressions`: `{expr}` entries in `.print` -> the V()/I() variables they reference.
   The comparison uses every node voltage and branch current, and ngspice ignores `.print` when it
   writes a rawfile.

## Results (ngspice-47, spice-ts at the PR head; see report.json)

Metric: absolute error on the first engine's output points, with the other side linearly
interpolated (breakpoint-aware for spice-ts vs ngspice TRAN, as in the aggregate). The analytic
references are evaluated exactly at each engine's own points.

| Fixture | Translation | ngspice | spice-ts | spice-ts vs ngspice, worst abs max | vs Xyce ref: ngspice | vs Xyce ref: spice-ts |
|---|---|---|---|---|---|---|
| capacitor-rc-transient | translated | success, 59 pts | success, 51 pts | v(1) 1.00 V (loss, #531) | v(1) 2.78e-4 V (analytic) | v(1) 1.00 V (analytic; `.ic` ignored, #531) |
| capacitor-rc-transient-newlte | unsupported-translation: `.options timeint newlte=2` selects a Xyce-only LTE algorithm; without it the deck is the same circuit, analysis and outputs as capacitor-rc-transient | not run | not run | n/a | n/a | n/a |
| capacitor-rc-oscillator | translated | success, 154 pts | success, 995 pts | v(1) 0.193 V, v(2) 1.16e-3 V (loss) | v(2) 3.42e-4 V (analytic) | v(2) 8.51e-4 V (analytic; first step, #532) |
| diode-level2-temperature-breakdown | unsupported-translation: Xyce LEVEL=2 diode (no SPICE3 level-2 diode, ngspice-47 rejects it) and `.step TEMP list` | not run | not run | n/a | n/a | n/a |
| diode-zener-5229 | unsupported-translation: Xyce LEVEL=2 diode; `.OPTIONS DEVICE` has no implemented rule | not run | not run | n/a | n/a | n/a |
| diode-transient | translated | success, 129 pts | success, 101 pts | v(3) 6.14e-4 V, i(vmon) 3.07e-7 A | v(3) 6.32e-4 V, i(vmon) 3.16e-7 A (gold) | v(3) 1.82e-5 V, i(vmon) 9.10e-9 A (gold) |
| njfet-stepped-dc | translated | success, 64 pts | success, 64 pts | i(vidmon) 5.98e-9 A | i(vidmon) 5.98e-9 A (gold) | i(vidmon) 4.9e-13 A (gold) |

The rc_osc v(1) number is not a simulator error. v(1) is the 100 kHz SIN source node, and ngspice
writes only about 7.7 points per period at the default maximum step, so linear interpolation of
the ngspice samples onto spice-ts's 995 points gives up to 0.193 V. The v(2) figures against the
analytic reference are the meaningful ones: both engines are well off at default tolerances, and
spice-ts is worse.
