# Issue 338 HFET/MESA singular-matrix receipt

This receipt covers the two unchanged ngspice fixtures named in issue #338. It fixes their false singular-matrix classification. It does not claim HFET, MESFET, behavioral-source, or waveform parity.

## Root cause and bounded fix

Both zero pivots had the same fixture-agnostic cause. `Circuit.expandSubcircuit()` silently discarded every device type absent from its switch. The HFET inverter therefore discarded both `Z` devices. The MESA oscillator discarded its `B` behavioral source and `Z` device. Their nodes remained in the compiled matrix without the missing device stamps, so sparse LU reported unrelated-looking zero pivots.

The fix makes the existing top-level parser boundary consistent inside subcircuits. An unsupported subcircuit device now raises `ParseError` before solve. It does not add tolerances, adapt fixtures, substitute JFET behavior, approximate device models, or change the aggregate artifacts.

The RED run reproduced all four batch/streaming assertions as `SingularMatrixError`. The GREEN run passed all four assertions with structured `ParseError` diagnostics.
